A category says what money was for. Its type says how omsync treats that money. One field carries both, so a category cannot be income and also a budget line.

{{ compare_table( ["Type", "What it means", "Examples in the demo"], [ ["Fixed", "A regular bill, planned as a fixed budget", "Rent, Utilities, Phone & internet"], ["Flexible", "Day-to-day spending you control", "Groceries, Dining, Coffee"], ["Non-monthly", "Irregular costs, funded across months", "Travel, Gifts, Home"], ["Unassigned", "An expense you have not classified yet", "Blue Bottle Coffee, until you choose"], ["Income", "Money that counts as income in reports", "Paycheck, Interest"], ["Excluded", "Money that reports leave out", "Transfer, Credit card payment"], ["Owed", "Money between you and a contact, such as a loan", "Loans"], ], "Category types", ) }}

Fixed, flexible, and non-monthly categories are what a budget plans. Excluded and Owed categories are left out of reports, and only contact balances read Owed money. A category can have an icon, which appears beside its name on the Categories page and in the budget.

A keyword is a text pattern that assigns a category. In the demo, NETFLIX assigns Subscriptions, and TRADER JOE assigns Groceries. Keywords live in lists. Unique keywords are specific, and they outrank Generic ones. Generic keywords are loose fragments of payee text, such as Zelle payment, which can sit in many descriptions.

Patterns ignore case. You choose whether a pattern is literal text or a regular expression. A pattern that is already in a list is refused, and a disabled keyword does nothing.

Categorize applies the keywords to transactions that have no category, and to those whose category a keyword or a rule set before. It never changes what you set yourself.

A rule sets a category when all of its conditions hold. Rules are tried in order. The first rule that holds sets the category, and the rest are skipped. A rule can read four things about a transaction:

  • the category that its keyword assigned, and optionally only the Unique or Generic list;
  • the amount, as a size: under a limit, at least a minimum, or a range between them;
  • the other side: a payment with a person, one contact, or one of your own accounts;
  • the account the transaction is in.

The demo has three rules, in this order:

  1. A transfer whose other side is Sam Park becomes Rent, so his half of the rent is rent.
  2. A transfer from the Generic list, of $100 or more, with a person becomes Loans. This is how the $300 to Priya Nair is a loan.
  3. A transfer from the Generic list, under $40, with a person becomes Dining.

Order matters. The first rule runs before the second, so Sam's $1,200 becomes Rent and not a loan. A transfer of $45 to or from Taylor Kim fits none of them, so it stays a transfer until you decide what it is.

{{ figure("categorize-rules", "The Rules tab: each rule as a sentence, with buttons to move it up or down, turn it off, edit it, or delete it.", "Rules are listed in order, each as its sentence.") }}

On the Rules tab you can preview a draft before you save it. The preview says how many transactions the rule would change and lists them, and it writes nothing. Saving, moving, or switching off a rule updates the categories at once.

{{ try_it("/settings/categories?tab=rules", "Open Rules", "Each rule is shown as a sentence, with the transactions it would change.") }} {% endcall %} {% call section("precedence", "What outranks what") %}

Your own choice outranks everything. A category you set by hand, and a split you make, stay until you change them. Receipts come next. Keywords and rules rank alike: each can replace the category the other set.

On a transaction's detail page, Set by rule names the rule that set its category, and it shows the rule's sentence. If a rule set the category but no longer holds, the page says so.

{% call callout("note", "Splits") %}

A transaction can be split into parts, each with its own category and amount. The parts must add up to the transaction's amount exactly. A split belongs to you, so categorize leaves it alone.

{% endcall %} {% endcall %} {% call section("undo", "Preview, apply, and undo") %}

Categorize is always a preview first. It shows what would change, and nothing is written until you apply it. Applying it is one batch, so the confirmation's Undo reverses all of it at once.

Undo refuses to overwrite later work. If you edited a transaction that categorize changed, the undo says so and changes nothing, so your edit is kept.

{{ try_it("/settings/categories", "Open Categories", "Preview categorize sits beside New category on the Categories page.") }} {% endcall %} {% call section("receipts", "Receipts") %}

A receipt explains what a purchase contained. A single Amazon or Costco charge can then be split into the categories of the items on its receipt. A receipt is matched to a charge that a tracked account paid, and applying it is a batch you can undo, like any other change.

The demo has no receipts. The repository's how-to, Run sync and obtain receipts, explains the vendor logins and the commands.
