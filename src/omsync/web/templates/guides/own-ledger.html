To run omsync on your own statements you need:

  • Python 3.12 or later, and uv to run it;
  • the Bitwarden command-line tool, bw, and your Bitwarden account, which signs you in and supplies the bank logins;
  • access to the macOS keychain, where the Bitwarden API client ID and secret are kept;
  • Chrome, if you want Bank sync to fetch statements from bank websites.

The demo needs only Python and uv. Your own ledger needs the rest.

{% endcall %} {% call section("setup", "Set up on your Mac") %}

From the omsync folder, run these in a terminal:

{% call steps() %} {% call step("Install the dependencies") %} 
uv sync
{% endcall %} {% call step("Store the Bitwarden API credentials") %}

Each command prompts you for the value. Do not put either one in a file or on the command line.

uv run keyring set omsync bitwarden-client-id
uv run keyring set omsync bitwarden-client-secret
{% endcall %} {% call step("Create the database") %} 
uv run omsync db upgrade

This creates your ledger. Until you run it, omsync serve shows the demo instead.

{% endcall %} {% call step("Check the setup") %} 
uv run omsync doctor

It reports anything missing, and starts no import or sync.

{% endcall %} {% call step("Start the server") %} 
uv run omsync serve

Open http://127.0.0.1:8765 and sign in with your Bitwarden vault email and master password.

{% endcall %} {% endcall %}

Optional settings live in ~/.config/omsync/omsync.toml, such as where the data folder is, the port, your vault email, and how long the vault stays unlocked. Set OMSYNC_CONFIG to use another file. Secrets never belong in that file.

{% endcall %} {% call section("accounts", "Add your accounts") %}

Each bank you use is a provider. The easiest way to add one is Settings → Bank sync → Add provider, which walks through the institution, the vault login, the accounts, and the mapping of statement accounts. The Bringing in your statements guide describes each step.

From a terminal, an account can be added directly. Use the account ID the statement reports, not just its last four digits:

uv run omsync accounts add --institution example --institution-name "Example Institution" \
  --statement-account STATEMENT_ACCOUNT_ID --name Checking --type checking

Treat the statement account ID as private. Your shell history keeps it, so the wizard in the app is the better choice when you can use it.

{{ try_it("/settings/providers", "Open Bank sync", "Add provider starts the five-step wizard.") }} {% endcall %} {% call section("first", "Bring in your first statements") %}

Put each statement file in the folder for its institution, inside your data folder. Then, from a terminal, preview and apply:

uv run omsync import
uv run omsync import --apply

The first command shows what each file would do, and writes nothing. The second applies it, with one batch for each file. Then categorize:

uv run omsync categorize
uv run omsync categorize --apply

Each of these is reversible. uv run omsync batches list shows the batches, and uv run omsync batches undo BATCH_ID reverses one.

{% call callout("tip", "Make a backup first") %}

Before your first real import, run uv run omsync backup create. The archive holds your statement files too, so one file keeps the whole record.

{% endcall %} {% endcall %} {% call section("demo", "Come back to the demo") %}

The demo is always there. uv run omsync serve --demo shows it even when you have a ledger, and it is made in a temporary folder that is deleted when the server stops. Your ledger is not touched.

Without a ledger, uv run omsync serve shows the demo, and prints one line that says so.

{% call callout("demo", "The demo and your ledger are separate") %}

Changes you make in the demo never reach your own data folder. Starting your ledger later does not bring the demo's Kunchorn along, and running the demo does not change your ledger.
