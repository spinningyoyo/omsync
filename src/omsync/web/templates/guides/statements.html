A statement is the file your bank gives you for one account and one period. omsync reads OFX and QFX files, the formats that bank and card statements come in, and the supported Bank of America CSV layouts.

Put each file in the folder for its institution, inside your data directory. That is ~/omsync-data unless your configuration says otherwise. The folder is the institution's key in capitals:

~/omsync-data/statements/BOA/4821/activity.csv
~/omsync-data/statements/CHASE/activity.ofx

A Bank of America CSV does not name its account, so its folder does: the last four digits sit in the folder's name. An OFX file carries its account ID inside the file.

omsync keeps each statement file as the institution wrote it. Each row keeps the fields the file reported, and a file already in the folder is never overwritten.

In the app, Settings has Bank sync. Its Add provider button starts a five-step wizard. Each step checks what it receives before it saves anything.

{% call steps() %} {% call step("Institution, provider and bank") %}

Give the institution a key, such as boa, and a display name. A provider key names this login's fetching and defaults to the institution key. Choose the bank that fetches the statements.

{% endcall %} {% call step("Vault login") %}

Choose the Bitwarden login that the provider uses to fetch statements. omsync keeps only a reference to it, never the password.

{% endcall %} {% call step("Accounts to sync") %}

Name each account you want omsync to fetch, with its last four digits and type, and mark it as joint if it is shared. You can add more later.

{% endcall %} {% call step("Map accounts") %}

Each statement account found in the folders needs a home. Choose a new account, an alias for an existing account (for a reissued card), or skip it for now.

{% endcall %} {% call step("Import") %}

Preview what the files would do, then import. Nothing is written until you press Import.

{% endcall %} {% endcall %} {% call callout("note", "Accounts without a provider") %}

A statement for an account that no provider fetches still imports from its institution's folder. In a terminal, uv run omsync import previews those files and uv run omsync import --apply imports them.

A preview reads each file and sorts every row into one of three outcomes:

  • Joined to a transaction omsync already has, when the evidence agrees.
  • Created as a new transaction, when the row is a movement of money it has not seen.
  • Sent to review, when the row may be an existing transaction but the evidence is unclear.

A preview writes nothing. Importing writes one batch for each file, so Undo can reverse one file on its own. Importing a file that is already in the ledger changes nothing. After an import that brings in anything new, omsync also links the matches that need no review, as a separate batch you can undo.

{{ try_it("/transactions/review", "Open Needs review", "Rows that are waiting for a decision are listed here, with the transactions they might be.") }} {% endcall %} {% call section("checks", "Balance checks and review") %}

Each statement carries the bank's balance on a date. After an import, omsync compares those balances with the transactions between them. When they disagree, the account shows a small warning dot in the Accounts panel, and its page shows the check.

The check only reports. It never adds a transaction to make a difference disappear. Open the transactions in the interval, compare them with the statement, and decide what is missing.

Some rows wait under Needs review on Transactions. Open one and look at the source row next to the transactions it might be. Choose Same as the existing transaction if it is the same movement, or Add as new transaction if it is genuinely separate. Do not add a transaction just to empty the list.

{% endcall %} {% call section("sync", "Bank sync, when you want it") %}

Bank sync can fetch the statement files for you. A sync runs one provider's connector, keeps the files it obtained next to your others, and imports them, one batch for each file. The Bank sync page has Sync all, and a Sync button on each provider card.

A sync needs your Bitwarden account, the Bitwarden command-line tool, and Chrome, because the bank connectors open a Chrome window for each bank. Keep that window open until the sync finishes. If a bank asks for a one-time code, the question appears on the page.

It needs a Bitwarden vault and your bank logins, so the demo does not run it. Kunchorn's accounts were filled from statement files, the same way you would bring in your own.
